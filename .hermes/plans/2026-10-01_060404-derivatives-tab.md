# Derivatives Main Tab — Implementation Plan

> Plan-mode deliverable. No code changes yet. Prepared 2026-10-01 (UTC) from the live
> workspace at `/home/ubuntu/.hermes/profiles/qr_frontend/workspace/jt-ai-trading-platform/`.

**Goal:** Add a 6th main tab, **Derivatives**, containing everything derivatives-related
(research, backtest, execution) so none of it leaks into or perturbs the existing 5 tabs.

**Architecture:** One self-contained vertical slice: `frontend/src/components/derivatives/*`
(lazy-loaded), its own sub-tab set, its own backend router `backend/app/routes/derivatives.py`
under the `/api/derivatives/*` prefix, and (later) its own `gold.derivatives_*` tables owned by
qr_etl. Zero edits to existing tab bodies, zero edits to existing backend routes, zero reuse of
existing ledgers.

**Tech stack:** React + Tailwind v4 (existing shell patterns), FastAPI router (new file), new
DB namespace (qr_etl-owned).

---

## 1. Containment contract (what this tab must NEVER touch)

The user's core requirement is isolation. Concretely:

1. **No changes to existing components.** Research / Strategies / Execution / Command / Settings
   code is untouched. The new tab is mounted additively in `App.jsx` next to existing branches.
2. **Separate backend namespace.** All new endpoints live under `/api/derivatives/*` in a new
   router file. Existing routers (`execution.py`, `strategies.py`, `hkex.py`, …) are not edited.
3. **Separate data namespace.** Derivatives ledgers live in NEW tables (e.g.
   `gold.derivatives_positions`, `gold.derivatives_backtest_runs`, `gold.derivatives_fills`) —
   NOT in `gold.paper_trades*`, `gold.paper_uat_fills`, `gold.trade_executions`,
   `gold.manual_positions`, or `gold.manual_orders`. Existing books and their P&L aggregates
   (`/api/command/pnl-by-mode`, `/api/execution/book-overview`) therefore cannot change.
4. **Separate strategy universe.** Derivatives strategies get their own asset classes
   (`OPTION` / `FUTURE` strategy rows) and their own list endpoint
   (`/api/derivatives/strategies`). They are NOT added to `gold.v_pipeline_ui_feed` /
   `/api/strategies/researcher`, so Lab / Pipeline / Performance counts, quality gates, and
   `ASSET_MAP` in `strategyProfiles.js` stay exactly as they are. (If the user later wants
   derivatives strategies visible in the shared Strategies workspace, that is a deliberate
   follow-up: extend `ASSET_MAP` + ask qr_etl whether the pipeline feed should include them.)
5. **No synthetic data.** Per house rule: until qr_etl lands real tables/feeds, every
   derivatives panel renders an honest PENDING / empty state naming the blocking qr_etl task
   in the tooltip. Nothing is fabricated serve-time or client-side.
6. **No broker routes initially.** Phase 1–2 has no IBKR order path for derivatives. If/when
   derivatives execution goes live, it gets its own guarded card (own confirm modal, own
   endpoint) — it does not reuse `/api/ib/place-order` from the Live book.

  `/api/derivatives/positions` (+ own book-overview style stats strip once backend lands).

Styling rules (house palette, enforced):
- Neutral slate/white surfaces (`qr-surface`, `bg-white/[0.03]`), blue = links only,
  rose = critical severity only, emerald/rose TEXT only for signed P&L via `pnlCl`.
- No new hues, no per-derivative-type color coding.
- Dense one-row strips; every panel header carries a LIVE / PENDING provenance badge with the
  blocking task id in the tooltip (never inline).
- No unbounded lists — scroll caps like `STAGE_SCROLL` pattern from IpoTab.

### 2.3 Mode parameter

URL is `/:mode/derivatives` so the global mode (sim/paper/uat/live) is available, but
**recommendation: the derivatives tab ignores the global mode in Phase 1–2** and shows its own
book selector inside Execution once real books exist (derivatives books are separate ledgers —
see §3). This avoids implying that `/live/derivatives` somehow trades through the existing Live
book. If the user prefers the global mode selector to drive derivatives books, that's a
one-line prop change later — call this out as an open question (§6).

## 3. Backend design (Phase 2 — after frontend skeleton is approved)

New file `backend/app/routes/derivatives.py`, registered in `backend/app/main.py` with
`prefix="/api/derivatives"` — the ONLY backend main.py edit, purely additive.

Phase 2 endpoints (honest-empty implementations, no fabricated rows):

| Method | Path | Response (shape) | Phase-2 behavior |
|--------|------|------------------|------------------|
| GET | `/api/derivatives/overview` | `{ strategies: n, open_positions: n|null, ... }` | nulls + `status: "pending_etl"` |
| GET | `/api/derivatives/strategies` | `{ strategies: [], count: 0 }` | empty until registry rows exist |
| GET | `/api/derivatives/backtests` | `{ runs: [], count: 0 }` | empty |
| GET | `/api/derivatives/positions` | `{ positions: [], count: 0 }` | empty |

Guards per house pattern: each endpoint wraps queries in `safe_query`, frontend normalizes
`{data}|{strategies}|[]` shapes defensively, and every consumer guards expected top-level keys
(the `ProgrammingError → 200 {data:[]}` fallback incident pattern).

DB namespace (qr_etl deliverables, Phase 3 — file kanban tasks, do NOT create tables ourselves):
- `gold.derivatives_strategies` (or registry rows tagged asset_class=OPTION/FUTURE — decide with qr_research)
- `gold.derivatives_backtest_runs` / `gold.derivatives_backtest_trades`
- `gold.derivatives_positions` / `gold.derivatives_fills` (per book: deriv_sim, deriv_paper, …)

## 5. Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| A 6th nav item crowds desktop header / mobile bottom nav | Verify at 1280/375px headless; `short: 'Drv'` label; mobile slice fix |
| Derivatives strategies leaking into shared Strategies workspace counts | Keep them out of `v_pipeline_ui_feed` / `/api/strategies/researcher`; own endpoint |
| P&L aggregates double-counting derivatives | Separate ledgers; `/api/command/pnl-by-mode` and `book-overview` untouched |
| Hotkey collision | Main keys 1–5 taken → use `6`; sub keys q/w/e free within this tab |
| Existing-tab regression from App.jsx edits | Additive-only edits; headless-verify all 5 existing tabs post-build |
| Backend restart leaving ghost uvicorn / IBKR client-id session | SIGKILL stale PIDs, check `ss -tnp 'dport = :14002'` before restart |
| User sees stale bundle after deploy | rsync --delete + live lazy-chunk hash verification (DerivativesTab-*.js) |
