# JT Trading Platform - Data Dictionary (v4.1)

## Overview
This document describes the 4-tier schema architecture implemented on the AWS RDS PostgreSQL instance. All timestamps are synchronized to **Hong Kong Time (HKT/UTC+8)**.

---

## 1. Bronze Layer (Raw)
*Schema: `bronze`*

| Table | Column | Type | Description |
| :--- | :--- | :--- | :--- |
| `raw_stock_data` | `date` | TIMESTAMP | Market date of the record. |
| | `ticker` | VARCHAR(20) | Trading symbol (e.g., NVDA, 0700.HK). |
| | `open/high/low/close` | FLOAT | Standard OHLC price data. |
| | `asset_category` | VARCHAR(20) | STOCK, FX, CRYPTO, or COMMODITY. |

---

## 2. Gold Layer (Intelligence Mart)
*Schema: `gold`*

### `asset_registry`
The central registry managing the platform's active universe.
*   `ticker`: Primary Key.
*   `asset_class`: Controls which worker processes the asset.
*   `horizon`: Short Term or Long Term bias.

### `stock_metrics`
Institutional-grade KPIs for equity analysis.
*   `pe_ratio_ttm`: Trailing 12-month Price-to-Earnings.
*   `free_cash_flow`: Net cash generated by the business.
*   `prophet_forecast`: 7-day machine learning prediction (%).

### `crypto_metrics`
Digital asset specific drivers.
*   `mvrv_z_score`: Market Value to Realized Value.
*   `nvt_ratio`: Network Value to Transactions.
*   `liquidations_24h_usd`: Simulated leverage flush volume.
*   `lsd_divergence_score`: Liquidity-Sentiment Divergence alpha.

### `fx_metrics`
Fiat currency drivers.
*   `interest_rate_diff`: Primary carry-trade driver.
*   `dxy_correlation`: Correlation to the US Dollar Index.
*   `market_regime`: Calibrated state (Bullish/Bearish/Stable).

## 3. Consumption Layer (UI-Optimized)
*Schema: `consumption`*

### `stock / fx / crypto / commodities`
These tables provide pre-joined, high-performance data for the frontend cards.
*   `final_score`: The composite Alpha Score (0.0 - 1.0).
*   `est_1d / est_7d / est_1m`: The triple-timeframe forecast matrix.
*   `sparkline`: JSON array of recent price points for graph rendering.

### `hft_matrix`
High-frequency intra-day analytics (Paper 3-5).
*   `liquidity_momentum`: SURGE, NORMAL, or LOW velocity.
*   `fusion_signal`: Quantformer-style merged signal.
*   `shock_warning`: CRITICAL, CAUTION, or NOMINAL geopolitical threat level.

### `inventory`
User portfolio management.
*   `win_loss`: Real-time P/L calculation based on live spot rates.
*   `analysis`: JSONB block containing AI Swarm exit/hold advice.

### `news_outlook`
LLM market-impact layer over `silver.historical_news`, written twice daily
(07:30 + 13:30 UTC) by the qr_research cron `news-outlook-daily`; read by
`GET /api/news/outlook` (Research > News tab).
*   `row_type`: `cluster` (per top story; joins to `/api/news/digest` stories
    via `category` + `cluster_key` = sha1-16 of sorted headline token set) or
    `outlook` (one per category per `run_date`).
*   `category`: US / HK / CRYPTO / FX / METAL.
*   `bias`: bullish / bearish / neutral / mixed; `horizon`: intraday / 1w / 1m;
    `confidence`: 0..1; `affected_assets`: text[].
*   `rationale`: free text — may carry `STALE FEED` / `DATA GAP WARNING`
    markers (stale upstream feeds); the UI renders them verbatim in rose.
*   `n_sources` + `source_latest` tie each row back to the real headline
    window; `model` records the generating agent/model.
*   Same-day reruns upsert on (run_date, row_type, category, cluster_key);
    history accumulates by `run_date`. The API serves only the max run_date.

## 4. Maintenance & Metadata
*Schema: `gold`*

### `metric_definitions`
The "White-Box" logic library.
*   `formula_raw`: The mathematical equation used for calculation.
*   `weight_impact`: CRITICAL, HIGH, or MEDIUM impact on the final score.
